#  算数漏洞

相信各位同学或多或少有听说过“溢出”的概念，这里就不再展开了，直接上例子吧

##  1. 整型上溢，整型下溢

假如我们有一个`uint4`的数据类型（4位无符号整型，即没有负数），那么它的范围就是0~15，而如果两个`uint4`进行相加，比如15+1，此时理论上应该等于16，但是16的二进制是`10000`，超出了4位的限制，因此计算机会只保留低4位作为结果，所以此时15+1=0，这就是整型上溢

同理如果是0-1，那么计算机会“借位”：从不存在的第5位借走一个1，也就是`0000-0001`变成了`10000-0001`，因此0-1=15，这是整型下溢

Solidity中确实会出现这种问题，不过在0.8版本之后如果出现溢出就会自动revert，简单来说就是抛出错误并将状态返回至代码执行前的初始状态，因此**如果Solidity版本≥0.8，那么整型溢出的可能性就比较低**

> Solidity 0.8引入了`unchecked`块，在这部分代码块中的整型溢出将不会抛出错误，不过基本上还是不用这个东西的

##  2. 除法精度损失

刚刚提到了加减法，乘法其实和上溢一类，这里就不再展开，但是除法呢？

学过C的同学们肯定知道，在C里面，`uint`的除法只会保留整数部分，而这正是Solidity中会出现的情况，**也就是说Solidity中的5/2=2**，这种除法导致的精度损失一般会在一些DEX（Decentralized Exchange，去中心化交易所）的代码中出现，一般都是在链上进行汇率计算的时候会出现

##  3. 数据截断

我们经常会对不同的数据类型进行转换，而如果不进行注意，很有可能导致数据截断

举个例子：

```solidity
contract Test {
    function test(uint x) public pure returns (uint192){
        return uint192(x*2);
    }
}
```

如果我们传入`6277101735386680763835789423207666416102355444464034512896`，也就是2的191次方，那么返回的应该是`uint192(2**192)`，但是`uint192`的数值范围最大只到`2**192-1`，因此如果进行如上的数据类型转换，最后返回的结果会是0（`uint`相关类型截取低n位，`bytes`相关类型截取高n字节）
